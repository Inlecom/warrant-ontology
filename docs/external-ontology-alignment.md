# WARRaNT KG Ontology — External Ontology Alignment (Informative)

Version 0.10-poc | 2026-09-06

**Status: INFORMATIVE ONLY**

All alignment is informative. No `owl:equivalentClass`, `owl:sameAs`, or property substitution assertions are added to the ontology files. Normative alignment is deferred pending consortium agreement.

---

## 1. W3C SOSA/SSN

**Sensor, Observation, Sample, Actuator (SOSA) and Semantic Sensor Network (SSN)**
Namespace: `http://www.w3.org/ns/sosa/`, `http://www.w3.org/ns/ssn/`

| WARRaNT term | External term | Semantic fit | Notes |
|---|---|---|---|
| `obs:Observer` | `sosa:Sensor` | close | SOSA:Sensor is restricted to physical sensing; obs:Observer includes analytical services |
| `obs:Measurement` | `sosa:Observation` | close | sosa:Observation includes feature-of-interest; WARRaNT uses obs:hasDependabilityMetric instead |
| `obs:Metric` | `ssn:Property` / `sosa:ObservableProperty` | close | WARRaNT Metric is at component level; SOSA ObservableProperty is at feature level |
| `obs:hasValue` | `sosa:hasSimpleResult` | exact | Both carry a scalar result |
| `obs:hasTimestamp` | `sosa:resultTime` | exact | Both carry the timestamp of the result |
| `obs:VirtualSensor` | `sosa:Sensor` | close | Software-only nature not captured by SOSA; note needed |
| `obs:AnalyticalService` | `sosa:Sensor` | partial | SOSA has no direct equivalent for computational analytical services |
| `obs:HealthEvent`, `obs:DetectionEvent` | — | none | WARRaNT-specific; no direct SOSA/SSN equivalent |

**Gaps:** SOSA has no concept equivalent to the health event or to an analytical reasoning agent. These are WARRaNT-specific.

## 5. GSN / SACM

**Goal Structuring Notation / OMG Structured Assurance Case Metamodel (SACM 2.3)**
Namespace: `http://www.omg.org/spec/SACM/`

| WARRaNT term | External term | Semantic fit | Notes |
|---|---|---|---|
| `assr:AssuranceClaim` | `sacm:Claim` / `gsn:Goal` | close | A claim that a requirement is met; WARRaNT adds a runtime status |
| `assr:Evidence` | `sacm:Artifact` (as evidence) / `gsn:Evidence` | close | Both represent evidence supporting or challenging a claim |
| `assr:supportsClaim` | `sacm:AssertedEvidence` | close | Evidence-to-claim assertion |
| `assr:Assumption` | `sacm:Claim` with assumed=true / `gsn:Assumption` | close | Explicit assumption whose invalidation is monitored |
| `assr:Requirement` | `sacm:Claim` (top-level) / `gsn:Goal` | partial | Requirements are modelled as first-class targets of claims rather than as claims |
| `assr:LivingDependabilityCase` | `sacm:AssuranceCasePackage` | partial | Container with a version-controlled baseline and runtime records |
| `assr:AssuranceLevel`, `assr:CertificationReadiness` | — | none | WARRaNT-specific evidence-confidence and readiness indicators |
| `assr:AssuranceScore` (node dependability score) | — | none | An operational-condition quantity, not an assurance argument element |

**Note:** WARRaNT records which evidence supports or challenges a claim and which requirement the claim addresses; it does not encode argumentation structure (strategies, contexts, justifications) and does not determine evidence acceptability.
